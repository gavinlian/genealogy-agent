# 族谱关系描述规范（结论稿）

> 版本：2026-05 · 适用于版本一 OCR → 版本二关系描述 → 主谱/图谱

---

## 1. 结论（先给答案）

**不要把族谱画成「文字版关系图」**（例如满屏 `A→B→C` 的图状叙述）。国际通用做法（GEDCOM 7.0）是：

| 层 | 存什么 | 本项目对应 |
|---|---|---|
| 人（INDI） | 姓名、性别、生卒、世代 | `persons` 表 |
| 家庭（FAM） | 父/母 + 子女列表 | 版本二「一行一家」或行内 `配/子/女` |
| 关系边 | parent_child / spouse | `relations` 表 |
| 证据 | 哪一页扫描图 | `pages[].image_path` + 版本一 OCR |

**版本二（关系描述）的正确形态**：**按谱页分页 + 按人分行 + 关系字段写在行内**。  
机器可读、Agent 可解析、人可对照改字——三者统一用同一套 **RDL（Relation Description Lines）** 格式。

**版本三（可视化组谱）** 是同一套数据的拖拽视图，不是另一种真相；定稿仍以版本二/三文字为准，拖拽只改 `persons/relations` 预览，确认后写入主谱。

---

## 2. 为什么不用「文字画图形」

| 方式 | 问题 |
|---|---|
| 纯叙述段 | Agent 难以稳定抽取实体与边 |
| 箭头图 ASCII | 竖排族谱信息丢失、无法对应页码 |
| 只有 JSON | 用户无法对照改字、OCR 校对困难 |

**RDL 行格式** 介于 GEDCOM 与 OCR 之间：每行一个「人」或「一家」，字段固定，规则引擎 + LLM 都能解析。

---

## 3. RDL 格式规则（版本二标准）

### 3.1 分页（与版本一 OCR 对齐）

多图/多页时必须带页眉，与 OCR 批量识别一致：

```text
===== 第 1 页 =====
（本页关系描述正文）

===== 第 2 页 =====
（本页关系描述正文）
```

单页可省略页眉；UI 仍按「第 1 页」展示。

### 3.2 人物行（核心）

```text
{世代} {姓名} [男|女] [字xxx] [生YYYY] [卒YYYY] [父{姓名}] [母{姓名}] [配{配偶}] [子{名1,名2}] [女{名1}]
```

**示例**

```text
===== 第 1 页 =====
一世 张公 男 字德明 生1920 配李氏 子张三,张四
一世 李氏 女 配张公
二世 张三 男 父张公 母李氏 生1950 配王氏 子张甲
二世 张四 男 父张公 母李氏
```

### 3.3 可选关系块（复杂谱面）

行内字段不够时，页末追加（与 GEDCOM FAM 等价）：

```text
【关系】
张公 → 张三（父子）
张公 → 张四（父子）
张公 配 李氏
```

### 3.4 禁止

- 前言、分析、总结（「根据谱文…」）
- Markdown / JSON 代码块
- 把「一世」「谱序」「长子」当人名
- 编造 OCR 中没有的人名

### 3.5 与 GEDCOM 的对应

| RDL | GEDCOM 7 |
|---|---|
| 一行一人 | INDI |
| 行内 `配` + `子/女` | FAM + HUSB/WIFE/CHIL |
| `父/母` 字段 | FAMC / 推断 parent_child |
| `===== 第 N 页 =====` | 来源页 / 多媒体关联（SOUR + PAGE） |

## 4. 流水线（产品步骤）

```
导入图片(可多张)
    ↓ 版本一：每页 OCR 原文（左图右字，按页切换）
    ↓ 版本二：每页 RDL 关系描述（左图右字，可展开本页 OCR 对照）
    ↓ 版本三（可选）：拖拽世代/配偶/子女可视化校对
    ↓ 预览关系图 → 确认写入主谱
```

| 步骤 | 左 | 右 | 数据 |
|---|---|---|---|
| 版本一 | 原图第 N 张 | OCR 原文第 N 页 | `pages[n].ocr_text` |
| 版本二 | 原图第 N 张 | RDL 第 N 页 | `pages[n].relation_text` |
| 版本三 | 关系图/世代槽 | 属性面板 | `persons` + `relations` |

---

## 5. Agent / 解析器约定

1. **先分页** → 再 **按行** → 再 **抽字段**（世代、配、子、父、母）
2. 同名不同世必须带世代前缀
3. 配偶必须成对出现或在 `【关系】` 块中用 `A 配 B`
4. 解析失败时保留原文，不静默丢人

配置文件：`config/genealogy_pipeline.json` → `relation_text_format` + `page_model` + `generation_model`  
提示词：`backend/agent/genealogy_prompts.py` → `RELATION_DESCRIBE_PROMPT_TEMPLATE`  
前端样板：`src/constants/relationTextFormat.ts`

## 5.1 世代算法（谱书世次 ≠ 数据库世次）

### 现状（已部分支持）

| 能力 | 代码位置 | 说明 |
|---|---|---|
| 解析「一世 / 第 N 世」 | `genealogy_builder._parse_generation_from_line` | **按谱面字面**读世代 |
| 始祖 + 起始代数 | `families.start_generation` | 如全谱从第 15 世起算 |
| 沿父子链重算 | `generation_engine.recalculate_generations` | 始祖=第 1 代，向下递增 |
| 字辈字段 | `persons.generation_name` / `generation_prefix` | 存「德/仁/义」等，**未用于推算世次** |

### 尚未支持（你提到的场景）

常见族谱并非「始祖永远 = 一世」：

1. **支谱/local_restart**：谱书从某支开编，**谱面「一世」= 全谱第 15 世**（你说的「从第 15 代起它是一代」）
2. **字辈世次（zibei）**：用「德→仁→义→礼」轮转推代，与「一世二世」并行
3. **合修/续修**：不同卷、不同支系用不同起点

当前系统若 OCR 出「一世 某某」，会**直接当成数据库第 1 代**，不会自动 +14。

### 结论：双轨世代模型

必须区分两个数，不能混在一个 `generation` 里：

| 字段 | 含义 | 来源 |
|---|---|---|
| **谱书世次** `source_generation` | 谱面写的「一世、二世…」 | OCR / RDL 行首 |
| **全谱世次** `canonical_generation` | 入库、排树、Agent 推理用 | 计算得出 |

换算公式（支谱模式）：

```text
canonical_generation = source_generation + generation_epoch_offset - 1
```

例：谱书「一世」、偏移 15 → 全谱第 **15** 世（offset 表示「谱书一世对应全谱第几世」）。

族谱级配置（写入 `families` / pipeline）：

```json
{
  "generation_scheme": "local_restart",
  "generation_epoch_offset": 15,
  "root_person_id": "…",
  "zibei_sequence": ["德", "仁", "义", "礼"]
}
```

| `generation_scheme` | 适用 |
|---|---|
| `absolute` | 全谱从始祖起编，谱面世次=全谱世次（默认） |
| `local_restart` | 支谱/续修：谱面从「一世」重计，需设 `generation_epoch_offset` |
| `zibei_assist` | 字辈辅助校验；谱面缺「第 N 世」时用字辈序推断，**不单独作主算法** |

### RDL 写法（支谱）

谱书世次照常写；若已知全谱世次，可在行尾标注（可选）：

```text
===== 第 1 页 =====
一世 张公 男 [全世15] 字德明 配李氏 子张三,张四
二世 张三 男 [全世16] 父张公 母李氏
```

解析器：有 `[全世N]` 则优先作 `canonical_generation`；否则用 `source_generation + offset`。

### 产品交互（待开发）

整理页增加 **「世代规则」**：

- 本谱「一世」对应全谱第 ___ 世（默认 1）
- 或点选始祖人物，系统自动沿父子链重算

**版本二 AI 提示词**需补充：保留谱书原世次，勿擅自改成从 1 起；若谱序/凡例写明「自某某公下传为一世」，提取 offset 写入元数据。

## 6. 版本三（可视化）方向（下一步）

参考 GEDCOM 家庭单元，UI 提供：

- 左侧：谱页缩略图 + 当前页 OCR/RDL
- 右侧：**世代槽**（一世、二世…）+ 从 OCR 高亮拖入人名
- 拖线或按钮：`配`、`子`、`女`（等价于写一行 RDL）

可视化只改结构预览；保存时 **回写 RDL 或直写 persons/relations**，以用户确认的版本为准。

## 8. 给使用者的最短说明

1. **版本一**：只管「图上的字」对不对，按页改 OCR。  
2. **版本二**：只管「谁是谁的父/母/配偶/子女」，按页写 RDL 行；可 AI 生成后再改。  
3. **不要**在版本二写分析文章；**要**一行一个人、关系写进行里。  
4. 多张图 = 多个页签，**一页一图一字一关系**，不要混在一屏大段里。
